# Codex privacy milestone 1: interim cold review

Reviewed checkpoint `a1f83dd` against base `60a7204`, the canonical plan and implementation worklog, and native source `54201ea65a3501d09a87c776376a0c16aa39db70`. The reviewer started without the implementation conversation and performed a read-only source review. This is not the final acceptance review.

**Verdict: not ready for acceptance or a finished PR.** The native policy finding was subsequently accepted as an explicit gap by Amir; other implementation and test work remains. Milestone 2 remains gated on milestone 1 being fully ready.

1. **Accepted gap, November 4: refreshed organization cloud requirements can defeat local privacy values.** Local managed analytics consent and primary-auth constraints survive cloud overrides. Feedback, update checks, remote control and explicit OTel exporters do not have the required local ceiling. Native refresh publishes policy in memory, so readonly caches and one-time checks cannot enforce the session lifetime. Refusing currently eligible accounts also cannot prove a personal account stays ineligible after auth refresh. Amir explicitly accepted organization-owned policy as a gap and required unmodified Codex. This finding no longer blocks acceptance under the amended contract. Remove the temporary account refusal; do not substitute ordinary-tool restrictions or claim a session-lifetime policy guarantee. Relevant native sources: [requirements ordering](https://github.com/openai/codex/blob/54201ea65a3501d09a87c776376a0c16aa39db70/codex-rs/config/src/loader/managed_requirements.rs), [cloud exclusions](https://github.com/openai/codex/blob/54201ea65a3501d09a87c776376a0c16aa39db70/codex-rs/config/src/requirements_layers/layer.rs), and [refresh publication](https://github.com/openai/codex/blob/54201ea65a3501d09a87c776376a0c16aa39db70/codex-rs/cloud-config/src/service.rs).
2. **P1: shared SQLite initialization is not serialized.** AIM calculates database grants but does not take a finite initialization lock. SQLx SQLite migration locks are no-ops. Native app-server initialization can cover eager databases under short locks; memory V2 and paginated history are lazy. No clean empty-history initializer has been established. Candidate roots must include separate logs as well as state roots. P15 must cover every required database and interrupted initialization. Do not use guessed schemas, per-account database copies, a lifetime mutex or a persistent preparatory server. See [SQLx migration locking](https://github.com/launchbadge/sqlx/blob/v0.9.0/sqlx-sqlite/src/migrate.rs#L139) and [native lazy database opening](https://github.com/openai/codex/blob/54201ea65a3501d09a87c776376a0c16aa39db70/codex-rs/state/src/runtime.rs).
3. **P1: existing File-backed MCP credentials lack the required transition.** The conversion codec and keyring helper do not constitute the one-time maintenance owner, durable admission block, stopped-consumer control, native File lock, recovery journal, backend publication and recovery sequence. The helper is not yet part of admitted installed artifacts. Native readback/logout tests prove compatibility and deletion only. Affected File-backed setups must retain their original working setup until transition is established. Unavailable keyring service does not authorize plaintext copies or a new product daemon.
4. **P2: named permission profiles are missing from the input inventory.** Legacy `sandbox_workspace_write.writable_roots` is corrected, but named profiles express filesystem paths as table keys and workspace roots as path-to-boolean entries. Native direct file operations outside cwd can therefore be denied by the outer boundary despite native permission. Establish retained native fixtures and actual admitted roots without rebasing permission rule strings or building another general loader. See [native permission structures](https://github.com/openai/codex/blob/54201ea65a3501d09a87c776376a0c16aa39db70/codex-rs/config/src/permissions_toml.rs).
5. **P2: exporter admission does not respect effective trust and precedence.** Checking every raw document can refuse an exporter that native ignores in an untrusted project or overrides from another layer. Inventory from inactive layers can also grant unnecessary paths. Resolve the effective privacy inputs narrowly using pinned native semantics; a config/read result obtained after telemetry starts is not a pretransmission oracle. See [native layering contract](https://github.com/openai/codex/blob/54201ea65a3501d09a87c776376a0c16aa39db70/codex-rs/config/src/loader/README.md).

The reviewer closed three earlier findings after source correction and focused remote regressions: ordinary launch no longer depends on PATH resolving to the approved build, independent tools retain `OPENAI_API_KEY`, and legacy writable roots receive write grants.

**Overbuild assessment:** no broad cut is justified merely by the size. Environment-local authority, relative-settings adaptation, one-time MCP conversion and native acceptance trace to explicit requirements. The shared Claude/native extraction largely moves common mechanics. Avoid a daemon, global process registry, generic environment restoration service, duplicated configuration decisions and lifetime session locks. That assessment does not certify unfinished behavior. Mac native acceptance, concurrency, nested tools, scheduling, migration, the final suite and a fresh finished-implementation review remain required. No acceptance case was complete at this review.
