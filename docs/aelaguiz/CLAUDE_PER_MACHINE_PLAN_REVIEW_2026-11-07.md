# Independent review of the Claude per-machine plan

Claude Opus 5.5 at high reasoning reviewed the plan against actual source before implementation, in fresh session `311a8ccd-f9f2-4e68-88ff-022d38109175`. It returned findings rather than approving the initial design. This record states how the canonical [plan](../CLAUDE_PER_MACHINE_PRIVACY_AND_LOGIN_2026-11-07.md) changed; the final implementation still requires its own cold audit.

| Finding | Disposition |
| --- | --- |
| Remote login lacked a concrete original-browser handoff | Added managed local login/logout commands and a native URL/callback stdio mode, using the existing offsite fixture and original browser validation. Destination owns PKCE/exchange; no primary/browser transfer. Prove this early on the isolated Linux VM. |
| Every relogin unnecessarily stopped sessions | Same-account/organization/environment relogin uses native refresh/storage/app-state locks and a classified merge. Actual identity transition/rebind retains the existing stopped-owner guard. Native overlapping refresh/relogin tests are required. |
| Alias convergence was unnecessary and would mix organizations | Removed the registry, locator and alias migration. Preserve one label/home and existing duplicate refusal; identity includes organization. |
| Command surface and legacy enrollment were unspecified | Managed Claude uses `aim claude login/logout`; explicit `aim login --provider anthropic` retains separate Prime/Pi legacy enrollment. Readiness/help name the local command. No claim that legacy harness credentials become machine-local. |
| Legacy health could disable independent local grants | Metadata excludes legacy reauth/credential health; managed readiness is local. |
| Raw environment marker could become a cross-account identifier | Store an account/organization/environment binding digest in vendor-visible state, with the raw anchor outside that state. |
| Generic OTel switches could break task programs | Use Claude-specific telemetry controls and prove stock traces as well as other diagnostic positive controls. Keep ordinary tool exporter environment intact. |
| Exact outside-file selection was unsettled | Separate source reading established native literal `Read(//absolute/file)` rules. Use that existing surface; selected file does not grant parent. The reviewer’s proposed new file-list configuration is unnecessary. |
| Missing default directories could fail native admission | The implementation must support future approved work roots using existing canonical-future validation, or demonstrate an equivalent minimal solution. Dropping an absent Downloads directory forever from that session would violate the stated future-work-area behavior. Small native admission changes may therefore be needed; do not add a policy engine. |
| Provider grants might invalidate each other | Test independent Linux/Mac authorization and alternating actual native refresh early. Local logout is separately a local-removal test. The proposed six-login minimum and waiting an entire access-token lifetime are reviewer-added gates, not user requirements; forced-due native refresh exercises the real refresh operation. Report the tested two-environment scope without claiming a provider-wide grant-limit guarantee. |
| Tools matrix duplicated old acceptance | Run existing retained workflows once for direct-account privacy; assigned-route cases cover route behavior, without duplicating every tools test. Include clipboard/drag image paths and actual native file/image results. |
| Transfer-command guards risked unnecessary machinery | Retire managed transfer enrollment; keep local grants out of shared state by construction, and test explicit legacy boundaries. |
| Lease removal had unstated side effects | Remove obsolete Redis-outage pauses, remote-busy exclusion and routine idle-session stopping with the copied-token lease. Keep local native coordination. |
| Legacy maintenance could overwrite the primary home | Establish a separate legacy native destination before local-primary enrollment is enabled. |
| Temp namespace exclusions added unnecessary restrictions | Removed proposed new temp denials/complement emitter. The user permits files in the work areas, including personal contents; preserve existing snapshot immutability and private account storage. Detached services already have separate disabling controls. |
| Unproven old installation IDs could be used until a later idle window | Not accepted as an automatic privacy fallback. First identity conversion waits for that account’s local owners to finish; the onboarding section states that one-time cost. Other accounts/machines and existing processes continue. |

The plan now explains the one-time runtime installation and login per account actually used on each host. It does not authorize a fleet shutdown, mass login, merge, vendor fork, daemon or broader child sandbox.
