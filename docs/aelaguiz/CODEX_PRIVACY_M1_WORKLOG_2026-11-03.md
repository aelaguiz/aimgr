## Native policy limitation found during implementation

The earlier design approval did not establish that the exact stock release can enforce every required value against refreshed cloud requirements. The implementation reviewer found a concrete unsupported case. Local managed `analytics.enabled=false` survives ordinary cloud configuration, and native strips cloud attempts to override local primary-auth requirements. Those controls remain valid. Cloud requirements can override local `feedback.enabled`, `check_for_update_on_startup`, `allow_remote_control` and explicit OTel exporters; local conflict handling warns rather than refusing. Forced MDM requirements can protect scalar values on Mac, but do not provide a portable, editable independent-collector recipient restriction.

The current implementation refuses an admitted remote-managed account/config-server source. This is a temporary fail-closed safeguard, **not** accepted completion of the plan's account-support requirement. A personal-plan snapshot can also become remote-policy eligible after native refresh; preexec eligibility inspection is not a lifetime guarantee. No supported cloud-disable switch or local immutable-policy constraint was found in the pinned release. Cache prefetch or a readonly cache does not close the in-memory/background path.

A scope decision is pending with Amir; no account-support reduction has been approved. Even approval of the currently proposed refusal would not by itself resolve the refresh gap. Do not mark milestone 1 ready, infer normal-use approval, or begin milestone 2 while this remains unresolved. An official native enforcement capability, or an explicitly approved different design, is required for the affected guarantees.
