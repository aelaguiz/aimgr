## The material corrections are incorporated

1. **Claude protections are scoped to the reviewed launcher.** The first draft described some controls as applying to “all AIM” launches. That could have incorrectly certified the four remote installations whose selected AIM checkout is `354be9e3`. The final text scopes artifact admission, GrowthBook and Remote Control settings to the reviewed current launcher, while the fleet table separately reports the older selections. The fleet receipt records the missing new modules and approved-runtime selector. The older commit also lacks `src/privacy/claude-settings.js`; the current module and runner establish the common ordinary/protected settings for the reviewed implementation. The correction prevents a reader from treating repository source as installed fleet protection.

2. **Automatic Guardian review-context retention is now named.** The final [failed-approval-review section](../../../AI_APP_PRIVACY_INVENTORY.md#automatic-local-retention-of-failed-approval-reviews) distinguishes automatic local capture from feedback upload. Official 0.166 `core/src/guardian/feedback.rs` captures the action, instructions and raw reviewer history after policy selects a failed review. `ext/guardian-reviewer/src/feedback.rs` excludes disabled-feedback and ephemeral sessions, selects the listed failure outcomes, and applies the 4 MiB record cap with instructions/history omission on overflow. `state/src/runtime/guardian_feedback.rs` establishes the 64-record, 8-per-thread and 8 MiB budgets; migration `0060_guardian_review_feedback.sql` establishes deletion by parent-thread cascade. `feedback/src/guardian.rs` and the app-server feedback processor establish the conditional `auto-review-failures.jsonl` attachment when logs are included. The inventory does not misrepresent this as unconditional background upload.

3. **External-client attestation is separate from hardware collection and device enrollment.** The final [app-server attestation section](../../../AI_APP_PRIVACY_INVENTORY.md#attestation-supplied-by-an-external-app-server-client) matches official 0.166. The app-server chooses a thread-associated live connection advertising `requestAttestation`, requests `attestation/generate`, and waits 100 ms. It wraps the opaque client token in version/status metadata; the core can forward that value as `x-oai-attestation` on supported requests. The model-provider implementation enables that pathway for ChatGPT authentication. These Rust files do not establish the external token's contents, lifetime, or a native hardware fingerprint generator. The inventory correctly leaves those unknown and distinguishes this token from the desktop remote-control signing key identity.
